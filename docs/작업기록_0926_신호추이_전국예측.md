## 1. 화면에 새로 생긴 것

위치: **AREA 0(관제 대시보드) 바로 아래, 전체 폭**입니다. 헤더에는 `신호 추이·예측` 바로가기가 생겼습니다.

기존 예측 그래프는 AREA 1의 반쪽 폭 스크롤 칸 안에 있어 눈에 잘 띄지 않았습니다. 그래서 예측도 이 패널로 옮겼습니다.

### 1-1. 요약 타일 3개

영월 예시입니다.

| 검색 신호 확정 | 지점 최고 배율 · 3월 | 검색 신호 → 첫 행정 조치 |
| --- | --- | --- |
| **2/15** (최고 10.79배, 임계 1.73배) | **13.5배** (단종장릉, 같은 달 영월군 1.28배) | **19일 앞섬** (사례 1건의 사후 확인) |

지역에 따라 타일 내용이 바뀝니다. 신호가 없으면 "없음", 지점 자료가 없으면 "자료 없음", 조치 사건이 없으면 "7일 최대 예상"이 뜹니다.

### 1-2. ① 신호 추이 — 검색 관심과 외지인 방문, 최근 1년

- **위 칸**: 검색지수의 전년 대비 배율(7일 중앙값), 임계선(1.73배)
  - 임계를 7일 이상 연속 넘은 구간은 붉은 띠로 칠합니다
  - 신호 확정일과 최고점을 표시합니다
- **아래 칸**: 외지인 방문자(7일 평균)를 전년 같은 요일과 나란히 그립니다
- **두 칸 공통**: 에이전트① 타임라인 사건을 번호 핀으로 세로로 관통시킵니다(개봉 → 방문 급증 → 검색 신호 → 혼잡 → 조치)
- 단위가 다른 두 지표는 한 축에 겹치지 않았습니다(이중 축 금지)

### 1-3. ② 관광지점 vs 시군구 총량 — 전년 같은 달 대비

- 지점과 총량을 **같은 잣대**로 한 그래프에 그렸습니다. 배율이라 로그축을 썼습니다
- 영월: **단종장릉 13.5배 · 청령포 11.9배 vs 영월군 1.28배**
  - 총량이 움직인 폭은 지점 증가폭의 약 1/45입니다
- 서식4 핵심 주장("총량은 지점 쏠림을 못 본다")을 그림 한 장으로 보여줍니다

### 1-4. ③ 7일 방문객 예측 (새로 그림)

- 최근 6주 실측 + **같은 날들을 7일 전에 예측한 값(백테스트)** + 앞으로 7일 예측 + 80% 구간
- "이 모델이 평소 얼마나 맞았나"를 예측과 같은 화면에서 봅니다(영월 오차 15.0%, 전국 8.98%)
- 피크일과 그 이유(광복절·3일 연휴 등), 요일별 방문 비중을 함께 보여줍니다

### 1-5. 모든 차트 공통

- 마우스를 올리면 값이 뜹니다(호버). "표로 보기"를 누르면 모든 값을 표로 읽을 수 있습니다
- 차트 아래에 출처 배지와 "해석 시 주의"를 붙였습니다
- 색은 dataviz 검증기에서 색각이상 구분·대비 등 6개 항목을 모두 통과한 조합입니다. 빨강은 임계·초과 같은 '상태'에만 씁니다
- 좁은 화면(태블릿 폭)에서도 넘치지 않습니다

## 2. 숫자를 믿어도 되는 이유

차트는 **판정을 새로 만들지 않습니다.** 이미 쓰던 정의를 화면이 그릴 수 있게 옮겼을 뿐입니다.

| 차트 요소 | 계산 출처 | 확인 |
| --- | --- | --- |
| 검색·방문 배율, 임계, 신호 구간 | `agents/signals.py` (D-12) | 영월 신호 확정 2/15·최고 10.79배 — 타임라인과 같음 |
| 지점 vs 총량 배율 | `analysis/src/forecast/point_level.py` | 단종장릉 13.5배·청령포 11.9배·영월군 1.28배 — 사례 문서와 같음 |
| 백테스트·예측 | `export_forecast.py` (검증된 h=7 모델) | 테스트 sMAPE 8.98% 재현 후에만 내보냄 |

**반올림 주의**: 영월군 3월 원값은 1.275배입니다. JS 기본 반올림(`toFixed`)은 부동소수점 오차 때문에 이 값을 1.27로 내립니다. 그래서 사사오입 함수를 따로 써서 문서와 똑같이 **1.28**로 나오게 했습니다.

**오해를 막는 문구**: 신호 추이 차트에 "검색 신호는 급증을 미리 알려주지 않는다(조기경보 AUC 0.217, 지점 판별 AUC 0.482)"를 caveat로 달았습니다. 스파이크를 크게 보여줄수록 "검색으로 예측된다"로 읽힐 위험이 있어서입니다.

## 3. 전국 확장

| 항목 | 내용 |
| --- | --- |
| 7일 예측 | 실제 시군구 **226곳 전부** 생성 (인천 합산 단위 2곳은 학습에만 쓰고 파일은 만들지 않음) |
| 저장 위치 | 사례 6곳은 `data/prod/`, 나머지 220곳은 `data/prod/regions/` (1.9MB) |
| 지역 선택 추가 | **여수시·속초시·인제군·울릉군** — 기존 에이전트 산출물 5종 + 예측 + 신호 추이 |
| 공유 링크 | 주소 끝에 `?region=geoje`처럼 붙이면 그 지역으로 바로 열림 (값: yeongwol, geoje, yeosu, sokcho, inje, ulleung, chungju) |

**서식4·사이트 문구 제안**
> "전국 226개 시군구의 7일 방문객 예측을 즉시 생성한다. 영월·거제 등 6개 지역은 신호 추이·지점 분석까지 시연한다."

"나머지 지역은 실시간 크롤링 준비 중"이라는 표현은 쓰지 않는 게 좋습니다. 이유는 두 가지입니다.
- 자료가 월 단위이거나 4일 지연이라 '실시간'이 사실이 아닙니다
- '준비 중'보다 '이미 된 것'을 말하는 편이 더 강합니다

## 7. 파일과 명령어

**새로 만든 파일**

| 파일 | 역할 |
| --- | --- |
| `analysis/src/forecast/export_signal_series.py` | 신호 추이 차트 데이터 생성 |
| `data/schema/signal_series.schema.json` | 위 데이터의 계약(스키마) |
| `data/prod/signal_series[_코드].json` | 사례 6개 지역 산출물 |
| `web/src/pages/SignalTrend.jsx` | 신호 추이·예측 패널 |
| `web/src/components/trend/` | 차트 3종(`SignalTrendChart`·`PointVsTotalChart`·`ForecastChart`) + `trend.css` |
| `web/src/components/common/chart/chartKit.js` | 차트 공용 도구(색·축·반올림) |

**다시 만들 때**

```bash
uv run python analysis/src/forecast/export_forecast.py --all      # 226개 시군구 7일 예측 (약 1분, DB 필요)
uv run python analysis/src/forecast/export_signal_series.py       # 사례 6개 지역 신호 추이 (6초)
uv run python analysis/src/forecast/freeze.py --check             # 확정수치 43개 대조
cd web && npm run dev                                             # 화면 확인
```

순서가 중요합니다. `export_signal_series.py`는 `export_forecast.py`가 남기는 백테스트 파일(`data/interim/forecast_backtest_h7.csv`)을 읽습니다.
