# merge 브랜치 기준 기능 이식 (재시작) — 대조 문서 + 이식

## Context

`integration/ui-develop-port`(9c0d503)에서 develop 컴포넌트를 ui 레이아웃에 배선했더니 화면이
일관성을 잃었다. **그 브랜치는 버리고 `integration/ui-develop-merge`(38c9d14)에서 다시 시작한다.**

기준선: **UI는 merge 화면을 최대한 그대로 둔다.** 빠진 기능은 새 화면 영역을 만들지 않고 이미 있는
컨테이너 안에 넣는다. 그리고 **새 마크업에 develop 시절 CSS를 재활용하지 않는다** — ui-improvement
클래스를 쓰거나, 없으면 ui 톤으로 새로 쓴다.

작업은 두 단계다. **A. 대조 문서(캡처 포함)를 먼저 만들고, B. 그 다음 이식한다.** 캡처를 먼저 하는
이유는 정적 분석으로는 안 잡히는 시각적 기능(배치·강조·상호작용)이 드러날 수 있어서다. 문서가 나온
뒤 B의 항목이 늘 수 있다.

### 측정으로 확인한 사실 (추정 아님)

`main.jsx`에서 시작하는 import 그래프를 세 리비전에서 계산했다.

| 리비전 | 코드 파일 | 도달 불가 |
|---|---|---|
| `origin/develop` (8eb975f) | 54 | 0 |
| `poolhan/ui-improvement` (65e7b16) | 60 | 15 |
| `origin/integration/ui-develop-merge` (38c9d14) | 78 | 31 |

1. **merge는 develop을 완전히 포함한다** (`merge-base(develop, merge) == develop` tip).
   web/src에서 **삭제된 파일 0건** — 유실은 "파일이 없다"가 아니라 "페이지가 더 이상 호출하지 않는다"다.
2. **merge는 ui-improvement에서 살아 있던 것을 하나도 잃지 않았다.**
   `(ui 도달 가능) − (merge 도달 가능)` = **공집합**. 병합 자체는 UI 측면에서 무손실이다.
3. ui 쪽 고아 4종(`RegionSummary`·`InterestChart`·`SignalSeriesChart`·`ReviewMatrixStatusCard`)은
   **ui-improvement에서도 이미 죽어 있었다.** 병합 손상이 아니므로 제외한다.
4. 이식 대상 = **develop에서 살아 있었는데 merge에서 죽은 24개 파일 + 살아남은 파일 내부에서 빠진 필드들.**

### CSS 소유권 — 이번 작업의 핵심 제약

`civic.css`와 `datalab-theme.css`는 **develop에 존재하지 않는다**(ui-improvement가 추가한 파일).
`index.css`는 ui가 develop 것을 물려받아 고친 파일이라 두 계열이 섞여 있다. 따라서 판정 기준은:

```bash
# > 0 이면 ui-improvement가 스타일을 입힌 클래스 = 써도 된다
git grep -c "<클래스>" poolhan/ui-improvement -- web/src/civic.css web/src/datalab-theme.css
```

측정 결과:

| 쓰지 말 것 (develop 전용) | 규칙 수 | 써도 됨 (ui 테마) |
|---|---|---|
| `.today-action*` | 23 | `.compact-details` (12), `.caveat-note` (6) |
| `.tour*` / `.tour__*` | 33 | `.policy-checklist-phase` (5), `.policy-checklist-progress` (2) |
| `.chat-source-chip*` | 6 | `.analysis-signal-list` (12), `.analysis-evidence-lead` (7) |
| `.chat-source-detail` | 4 | `.analysis-type-list` (8), `.analysis-block-heading` |
| `.chat-widget__suggestions` | 1 | `.content-feed-card` (8), `.daily-peak-next` (18) |
| `.checklist-waiting` | 3 | `.briefing-item` (10), `.section-block` (2), `.info-box` (2) |
| `.region-coverage` (2), `.substitute-note` (1), `.tier-card*`, `regionSearch.css`, `trend.css` | — | `.chat-popup-launcher` (2) |

**규칙: 새 마크업은 위 오른쪽 열 클래스만 쓴다. 필요한 게 없으면 `datalab-theme.css`에 ui 톤으로
새로 쓴다.** develop 클래스 이름을 그대로 가져오면 규칙이 `index.css`에서 붙어 ui 톤과 어긋난다.

### 지난번 실패에서 가져갈 것

`RegionSearch`·`ChatWidget` 두 번 다 "develop 쪽이 커 보여서 ui 컴포넌트를 통째로 교체" → 그 ui
컴포넌트를 위해 쓰인 테마 CSS가 죽으며 화면이 깨졌다. **컴포넌트를 바꾸지 않고 기능만 얹는다.**

`trend.css`는 조사 결과 element 선두 규칙 0개, 살아있는 JSX가 쓰는 미scoped 클래스 규칙 0개였다.
지난번 붕괴는 스타일시트 탓이 아니라 `className="panel-trend"`를 렌더했기 때문이다
(`grid-area: trend`가 활성 `grid-template-areas`에 없어 암시적 트랙 생성).

# A. 대조 문서 만들기 (캡처 포함)

## A-0. 환경 (전부 확인됨)

Chrome `C:\Program Files\Google\Chrome\Application\chrome.exe`, Python PIL 12.3.0, npm 도달 가능,
Vite `publicDir: ../data`라 `/prod`·`/mock`이 리포 `data/`에서 그대로 서빙된다.

```bash
# develop UI를 현재 작업트리와 별개로 띄운다 (현재 브랜치 안 건드림)
git worktree add "$SCRATCH/ui-develop" origin/develop
cmd //c mklink //J "$SCRATCH\ui-develop\web\node_modules" "...\tourism-early-warning\web\node_modules"
(cd "$SCRATCH/ui-develop/web" && npx vite --port 5201)   # develop UI
(cd web && npx vite --port 5202)                          # merge UI (대조용)
```

Playwright는 **리포가 아니라 스크래치패드에 설치**한다(`web/package.json` 안 건드림):
`npm i playwright --prefix "$SCRATCH"` + `npx playwright install chromium`.
Playwright를 쓰는 이유는 `locator.screenshot()`으로 **요소 단위 크롭**이 되기 때문이다 — 전체
스크린샷을 좌표로 자르는 방식은 레이아웃이 바뀌면 깨진다.

## A-1. 캡처 스크립트

스크래치패드에 캡처 스크립트 하나를 둔다. 입력은 `{슬러그, 지역, 셀렉터, 펼칠 details, 설명}` 표.
동작: 지역 URL(`?region=51750` 등)로 이동 → 해당 요소 대기 → 안에 `<details>`가 있으면 전부
`open` → `locator.screenshot()`. develop과 merge **양쪽에서** 같은 방식으로 찍어,
"비슷한 기능"이 있는 항목은 나란히 보여준다.

지역은 **영월(51750, 사례 지역·데이터 최다)** 을 기본으로 하고, 사례 지역에만 있는 계약
(`checklist`·`precedent`·`timeline`·`hotspots`·`visitor_profile`)이 필요한 항목은 **거제(48310)**,
전국 일반 지역 동작 확인이 필요한 항목은 **종로(11110)** 를 쓴다.

죽어 있었다.
