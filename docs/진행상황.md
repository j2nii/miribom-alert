### 에이전트② 실행 (실데이터)

#### 에이전트②가 하는 일

시스템은 5개 에이전트로 구성되며, ②는 **콘텐츠 유형 분류**를 맡는다.

```
유튜브 수집 (collection/)
        ↓
   에이전트②  ← 여기
   "이 영상이 어떤 성격의 방문 수요를 만드는가"
        ↓
content_type.json  →  AREA 2 화면 / 에이전트③ 매칭의 보조 필터
                   →  poi_mentioned가 hotspots와 조인되어 "어느 지점에 쏠리는가"
```

- **입력**: `data/raw/youtube/{지역}_{시각}.json` — 제목·설명·태그·조회수·채널
- **출력**: `data/prod/content_type.json` (스키마 `data/schema/content_type.schema.json`)
- **프롬프트**: `agents/prompts/agent2_content_type.md` v1.0

중요한 것은 **콘텐츠를 평가하는 게 아니라 사람의 이동을 예측한다**는 점이다. 같은 지역 영상이라도 만들어내는 수요의 모양이 다르다. "맛집 7곳 순회" 영상은 소수 점포에 대기열을 만들고, "수국 명소" 영상은 넓은 자연 공간으로 방문을 분산시킨다. 전자는 점포 주변 동선 관리가, 후자는 주차·진입 관리가 필요하다. 즉 **유형이 곧 대응 방식**이다.

#### 왜 LLM이어야 하는가 (키워드 필터로는 불가능하다는 실증)

이번 수집에서 결정적인 사례가 나왔다. 두 영상은 **같은 인물, 같은 시기, 같은 해시태그**를 쓰지만 성격이 정반대다.

| 영상 | 조회수 | 분류 | 이유 |
| --- | --- | --- | --- |
| 「원이의 사투리 특강」 | 1,897만 | **관광무관** | 사투리 강의 형식으로 방문할 장소 정보가 전혀 없음 |
| 「갸루와 거제에 왔습니다」 | 1,394만 | **예능·방송 노출형** | 인물의 거제 방문 자체가 콘텐츠이며 이후 확산의 기점 |

둘 다 `#거제도 #거제여행 #리센느 #원이` 태그를 달고 있다. **키워드·해시태그 기반 필터는 이 둘을 구분할 수 없다.** 반대로 "예능 영상은 노이즈"라고 일괄 제거하면, 정작 수요를 만든 진원지를 통째로 버리게 된다. 영상이 무슨 이야기를 하는지 읽어야만 구분되며, 이것이 이 단계에 LLM을 쓰는 이유다.

#### 프롬프트를 이렇게 설계한 근거

| 설계 | 근거 |
| --- | --- |
| 분류 목적을 "콘텐츠 성격"이 아니라 **"만들어내는 수요의 모양"**으로 정의 | 유형이 대응 조치로 연결되어야 의미가 있다. 매뉴얼도 유형별로 관리 방안을 달리 제시한다(p.13) |
| `예능·방송 노출형` 유형 신설 | 거제 실측에서 조회수 상위 10건 중 8건이 인물 결부 콘텐츠였다. 기존 6개 유형(맛집·포토스팟·체험·축제·자연경관·촬영지)으로는 담기지 않으면서, **확산 속도가 가장 빠르고 지점 집중도가 높은** 유형이다 |
| `관광무관` 유형 신설 + **제외 건수 표시** | 지역명만 겹치는 콘텐츠(타 지역 여행기, 지역경제 분석)를 걸러야 하지만, 조용히 버리면 "무엇을 걸렀는지" 검증할 수 없다. 필터링 과정을 드러내는 것이 신뢰성의 근거다 |
| **유형 하나만** 선택 + 타이브레이커 규칙 | 맛집과 예능이 겹칠 때 *"이 영상이 없었다면 그 점포에 갔을까"*로 판정한다. 인물 때문에 간 것이면 예능형이다. 다중 라벨을 허용하면 집계 비중이 무의미해진다 |
| **근거(evidence) 필수** — 영상의 실제 표현 인용 | 매뉴얼 조치에 쪽수를 남기는 것과 같은 원칙이다. 추측으로 쓴 근거는 금지하며, 스키마에서 `evidence`를 required로 강제한다 |
| 신뢰도 0.6 하한, **애매하면 낮게** | 제목만으로 판단이 서지 않는 종합 코스 안내 등을 억지로 분류하지 않는다. 미달분은 집계에서 빠지되 건수로 남는다 |
| `poi_mentioned` 추출 | 이 값이 `hotspots.json`과 조인되어 **"콘텐츠가 어느 지점으로 사람을 보내는가"**를 만든다. 유형 분류만으로는 현장 대응 지점을 특정할 수 없다 |
| `sentiment` 병기 | 유형 축만으로는 과열 징후를 담을 수 없다. 「거제 바가지, '확답' 듣고 왔습니다」(19.6만)는 유형상 예능 노출형이지만 **sentiment=부정**으로 잡혀 과열 신호가 된다 |

#### 실행 방법 (재현)

```bash
uv run python collection/youtube_collect.py --region 거제 \
    --queries "거제도 여행" "거제 가볼만한곳" "거제 맛집" --limit 25 --days 120
uv run python agents/agent2_apply.py
```

`agents/agent2_apply.py`의 `RESULTS` 표가 프롬프트 실행 결과이며, 재실행 시 이 표를 교체한다. 스크립트는 판정 결과를 원본 수집 데이터와 조인해 스키마 형식으로 내보내는 역할만 한다 — 분류 로직이 코드에 숨어 있지 않다.

#### 현재 한계 (v1.1에서 다룰 것)

1. **종합 코스형 유형이 없다.** 숙소·맛집·관광지를 모두 다루는 안내 영상 2건을 단일 유형으로 특정하지 못해 신뢰도를 0.5 미만으로 낮췄다. 유형 체계 보완이 필요하다.
2. **제목·설명·태그 텍스트만 사용했다.** 영상 내용을 시청해 검증하지 않았고, 자막(captions)도 쓰지 않았다.
3. **데드존 신호를 버리고 있다.** 「해금강 마을, 호텔도 횟집도 파리만 날린다」는 관광무관으로 분류했지만, 같은 지역 안의 **핫존-데드존 격차**(매뉴얼 Tier1 KPI '지니계수')를 보여주는 신호다. 별도 축으로 살릴 방법이 필요하다.
4. **검색 결과 상위만 수집**해 소규모 채널이 과소 대표된다. 조회수는 수집 시점 기준으로 계속 변동한다.

**지금 바로 시작 가능하다. 기다릴 것이 없다.**

3. 공통 컴포넌트를 먼저 만들 것: `source` / `period` / `caveat` 표시 배지, `_mock: true`일 때 샘플 데이터 배너
4. `data/prod/content_type.json`은 **이미 실데이터다.** AREA 2 화면은 목업이 아닌 진짜 데이터로 만들 수 있다

우선순위: Vercel 배포 URL 확보 → AREA 0 관제 대시보드 → 나머지 4개 화면 골격

### 데이터팀 (매뉴얼 구조화)
1. `manual/README_태그체계.md` 읽기 — 필드 설명과 값 목록이 전부 정리되어 있다

| JSON 키는 영문, 매뉴얼 구조화 산출물만 한글 키 | 전자는 React가 소비하는 계약, 후자는 사람이 손으로 채우는 파일 |
| 단계 축을 `alert_level`(관심·주의·경계·심각)과 `congestion_level`(1~5)로 분리 | 매뉴얼이 두 체계를 별도로 쓴다. 전자는 경보, 후자는 밀도 측정 등급 |
| `content_type`에 `예능·방송 노출형` 추가 | 거제 사례의 진원지가 이 유형이며 확산 속도가 가장 빠르다 |
| `content_type`에 `관광무관` 추가 | 지역명만 겹치는 콘텐츠를 걸러내되 **제외 건수를 표시**하기 위해 |
| `before_after`의 KPI를 매뉴얼 11개 지표 enum으로 고정 | 우리가 성과 지표를 지어낼 수 없게 구조적으로 차단 |
| `data/prod/*.json`은 gitignore 예외로 추적 | 웹이 직접 읽는 제품이며 건당 수 KB |

## 산출물 위치

```
data/schema/       9종 스키마 + 공통 봉투          ← 계약. 변경 시 양쪽 합의 필요
data/mock/         목업 9종 (거제)                ← 역할3가 화면 만들 때 사용
data/prod/         실데이터 산출물                 ← content_type.json 완료
data/raw/youtube/  수집 원본 (gitignore)
manual/            태그 체계 + 샘플 5건            ← 데이터팀 작업 대상
agents/prompts/    에이전트 프롬프트
docs/manual-source/ 매뉴얼·연구보고서 PDF + 출처 안내
```

### 실행 명령

```bash
uv sync                                          # 환경 구성

uv run python collection/youtube_collect.py --region 거제   # 유튜브 수집
uv run python agents/agent2_apply.py                       # 에이전트② 결과 반영
uv run python scripts/gen_mock.py                          # 목업 재생성

uv run python scripts/validate_data.py data/mock           # 데이터 계약 검증
uv run python scripts/validate_manual.py                   # 매뉴얼 구조화 검증
```

`.env`에 `YOUTUBE_API_KEY`가 필요하다 (`.env.example` 참고). 쿼터는 하루 10,000 units이고 검색 1회가 100 units다.
