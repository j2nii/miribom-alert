# 계량성과 후보 — 09.13 회의 안건

> 작성 2026-09-12 · 역할4 · **회의에서 4~5개를 확정한다.** 확정된 항목이 곧 역할1·2의 분석 지시가 된다.
> 이 문서의 숫자 칸(N)은 비워 두었다. 분석 전에 숫자를 적지 않는다.

---

## 왜 지금 정해야 하나

심사 배점에서 **효과성 및 성과 창출도가 30점**이고, 서식4 예시는 전부 "방문객 200% 증가" 같은 **실행 성과**다. 우리는 실제 운영 실적이 없으므로 **백테스트로 숫자를 만든다**(v3 결정). 무슨 숫자를 낼지 먼저 못 박지 않으면, 분석이 끝난 뒤에 "이 결과로 무엇을 말하지"가 된다.

고르는 기준은 세 가지다.
1. **공사 매뉴얼 KPI이거나 우리 시스템 고유 지표**일 것 — 우리가 지표를 지어내지 않는다
2. **W1 수집 데이터로 실제 계산할 수 있을 것** — 못 내는 지표를 고르면 분석 뒤에 되돌아온다
3. **서식4 한 문장으로 쓸 수 있을 것**

### 핵심 ② 사전 탐지 적중률 · 오경보율 — 백테스트

| 항목 | 내용 |
| --- | --- |
| 정의 | 적중률 = 과거 급증 사례 중 급증 **전에** '주의' 이상을 낸 비율. 오경보율 = 급증이 없던 대조군에서 '경계' 이상을 낸 비율 |
| 계산 | 적중 사례 수 ÷ 전체 급증 사례 수 / 오경보 건수 ÷ 대조군 관측 기간 |
| 사례 | W1 7일차 결과물 — 전수 방문자수에서 **데이터가 고른 스파이크 지역 목록** + 대조군 3곳 |
| 데이터 | 방문자수 API 시군구 월간 전수(정답 라벨), 네이버 검색어 일간 |
| 담당 | 역할2 |
| 실현 가능성 | **중간** — 정답 라벨이 월간이라 해상도가 거칠다. 사례가 10건 미만이면 비율 대신 "N건 중 N건"으로 쓴다 |

> 서식4 예문: "2025.01~2026.08 급증 사례 N건 중 N건을 사전 탐지했으며, 대조군에서의 오경보는 N건이었다."

**오경보율을 반드시 같이 낸다.** 적중률만 내면 "항상 울리면 100%"라는 반론에 답할 수 없다.

### 핵심 ③ 핫존-데드존 균형도(지니계수) — 매뉴얼 Tier1 KPI

| 항목 | 내용 |
| --- | --- |
| 정의 | 거제 안에서 방문이 특정 지역에 얼마나 쏠렸는가. 0이면 고르게 분산, 1에 가까울수록 한곳에 집중 |
| 계산 | 읍면동별 월 방문자 수의 지니계수. **5/22 이전 3개월 vs 이후 3개월** 비교 |
| 데이터 | 데이터랩 '성/연령별 방문·소비 현황'(읍면동 단위, 역할1 문서 기준) |
| 담당 | 역할2 (계산), 역할1 (읍면동 데이터 확보) |
| 실현 가능성 | **중상** — 읍면동 월별 수치를 기간으로 받을 수 있는지 확인 필요 |
| 매뉴얼 연결 | p.15 Tier1 '핫존-데드존 균형도(지니 계수)' 그대로 |

**이 지표를 추천하는 이유**: 우리 문제 정의의 핵심 주장인 "콘텐츠 확산이 **특정 지점으로** 수요를 쏠리게 한다"를 **공사 매뉴얼 지표로** 증명한다. 에이전트②가 찾은 데드존(해금강마을)과 핫존(순대리아 등)이 숫자로 뒷받침된다.

> 서식4 예문: "콘텐츠 확산 이후 거제 읍면동 간 방문 집중도(지니계수)가 N에서 N으로 상승하여 특정 지역 쏠림을 확인했다."

### 보조 ④ 권고 조치의 매뉴얼 근거 명시율 · 오권고 0건

| 항목 | 내용 |
| --- | --- |
| 정의 | 시스템이 제시한 조치 중 매뉴얼 원문·쪽수가 붙은 비율 / 선행 신호만으로 현장 통제 조치를 '발동'한 건수 |
| 값 | 100% / 0건 — **설계로 보장된 값**이다 (D-07·D-08, 시나리오 테스트 완료) |
| 담당 | 역할4 |

**주의**: 이것은 '성과'가 아니라 '신뢰성'이다. 효과성(30점) 칸이 아니라 창의성·신뢰성 서술에 쓴다. 성과처럼 쓰면 심사위원이 "당연한 것 아니냐"고 본다.

### 보조 ⑤ 거제 대응(6.12) 전후 비교 — 논의 필요

| 항목 | 내용 |
| --- | --- |
| 정의 | 6.12 이전·이후 같은 길이 구간의 방문자 수, 관광소비 추이 |
| 데이터 | 데이터랩 이동통신 방문자수, 관광소비(역할1·2) |
| 문제 | **6.12 캠페인은 바가지(가격) 대책이다.** 매뉴얼의 혼잡 KPI로 효과를 재면 논리가 맞지 않고, 전후 차이도 계절성(6월 → 7월 성수기)과 섞인다 |

**회의에서 정할 것**: 이 항목을 쓸지, 쓴다면 "혼잡 개선"이 아니라 "빠른 대응 사례의 결과"로 쓸지. 역할4 의견은 **보조로 두되 효과 주장은 하지 않는 것**이다. `before_after.json`의 KPI enum이 매뉴얼 11개로 잠겨 있어, 가격 대책의 효과를 담을 칸도 없다.

## 고르지 않은 매뉴얼 KPI와 이유

| KPI (p.15) | 제외 이유 |
| --- | --- |
| 단위 면적당 인원수(경사도 보정) | 구역 면적·실시간 인원 데이터 없음 |
| 혼잡 임계치 초과 횟수/지속시간 | 밀도 실측 없음 (임계값은 p.53에 있으나 적용할 값이 없다) |
| 병목 구간 체류 시간 | 현장 센서 데이터 없음 |
| 실시간 혼잡도 단계 · 구간별 이동 속도 · 핫스팟 체류 인원 · 안전사고 위험도 | 실시간·센서 데이터 없음 (Tier3 전체) |
| 공간가치 효율성 지수 | 체류시간 데이터 없음 |
| 전년 대비 혼잡도율 개선 | '혼잡도율'을 만들 밀도 데이터가 없다. 방문자 수 증감으로 대신하면 매뉴얼 지표를 우리가 바꿔 쓰는 셈이다 |
| 유입/유출 비율 | 데이터랩 유입·유출 탭이 상위 3곳만 줘서 비율 계산이 어렵다 |

**서식4에 이 표를 요약해 넣을 것을 권한다.** "측정할 수 없는 것은 측정하지 않았다"는 서술이 데이터 활용의 구체성(30점)을 오히려 강하게 만든다.
