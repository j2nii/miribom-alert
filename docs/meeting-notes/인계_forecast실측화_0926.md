## 2. 먼저 알아야 할 제약 3가지 ⚠

작업을 시작하기 전에 이걸 모르면 **틀린 숫자를 화면에 올리게 된다.**

### 2-1. 스키마는 90일을 상정하지만, 우리가 검증한 것은 7일 앞이다

- `data/schema/forecast.schema.json`의 `daily`는 "예측 대상 90일"이라고 적혀 있다
- 그러나 우리가 성능을 잰 것은 **h=7(7일 앞)뿐**이다. 90일 앞 성능은 측정한 적이 없다
- 다행히 스키마는 `"minItems": 1`이라 **7일치만 채워도 규격 위반이 아니다**
- **90일을 채우고 h=7 성능을 붙이면 거짓이 된다. 절대 하지 말 것**

### 2-2. 데이터 기준일이 2026-08-14다

- 시군구 일별 방문자 데이터는 2026-08-14까지 있다
- 따라서 예측 대상은 **2026-08-15 ~ 08-21**이 된다. 오늘 기준 "다가오는 7일"이 아니다
- envelope의 `caveat`에 **"데이터 기준일 2026-08-14 기준 7일 앞 예측"**을 반드시 적는다
- 화면에서 미래처럼 보이면 안 된다

### 2-3. metric enum에 sMAPE가 없다

- 스키마가 허용하는 것은 `MAPE`·`RMSE`·`MAE` 셋뿐이다
- 우리 주력 지표는 sMAPE(8.98%)인데 enum에 없으므로 **`MAE` 7,603명을 쓰고 sMAPE는 caveat에 병기**한다
- 스키마를 고쳐 sMAPE를 추가하는 방법도 있지만, 프론트·에이전트⑤가 이미 이 필드를 읽고 있으므로 건드리지 않는 쪽이 안전하다

### 2-4. 일별 `expected_alert_level`은 비워둔다

- 우리 경보 단계(관심/주의/경계/심각)는 **월별 3신호 판정(D-13)**이라 일별 임계가 없다
- 스키마상 optional이므로 넣지 않는다. 지어내면 발명 금지 원칙 위반이다
- 단, `peak_days`의 `expected_alert_level`도 같은 이유로 생략하거나, 넣어야 한다면 근거를 먼저 만든다

## 3. 만들 것 — 출력 규격

`data/prod/forecast_51750.json`, `data/prod/forecast_48310.json`

```
envelope
  _mock         false
  generated_at  생성 시각 (KST)
  source[]      이동통신 기반 시군구 일별 방문자(공공데이터포털 15101972),
                한국관광 데이터랩 월간 지표
  period        {start: 2026-08-15, end: 2026-08-21, granularity: "일"}
  caveat        "데이터 기준일 2026-08-14 기준 7일 앞 예측. 검증 sMAPE 8.98%(MAE 7,603명),
                 228개 시군구 공통 모델, 테스트 2026-01-01~08-14 51,528건.
                 90일 예측은 검증하지 않았으므로 제공하지 않는다."

data
  region        {code: "51750", name: "영월군"}
  model
    name        "부스팅 회귀(HistGradientBoosting) — 방문자 시차 + 달력 + 축제 + 검색 + 데이터랩 월간"
    trained_on  {start: 2023-01-01, end: 2025-12-31, granularity: "일"}
    metric      {name: "MAE", value: 7603, validation_period: {2026-01-01 ~ 2026-08-14}}
    features    ["방문자 시차(4일 지연 공개 반영)", "요일·공휴일·연휴길이", "축제 전후",
                 "네이버 검색지수(전일까지)", "데이터랩 월간(익월 17일 공개 반영)"]
  daily[7]      {date, predicted, lower, upper, is_holiday}
  weekday_concentration[7]   최근 1년 요일별 방문 비중, 합 1.0
  peak_days[]   예측 7일 중 상위 1~2일 + reason(주말/공휴일 등 사실만)
```

### 구간(lower/upper)을 만드는 법

**검증 구간(2026-01-01~08-14)의 잔차 분위수**를 쓴다. 모델이 구간을 직접 내놓지 않으므로,

1. 그 지역의 검증 구간 `실제/예측` 비율을 모은다
2. 10분위·90분위를 구한다 → 80% 구간 배율
3. `lower = predicted × q10`, `upper = predicted × q90`

지역별로 따로 구해야 한다(지역마다 오차 폭이 다르다). 표본이 부족하면 전국 분위수로 대체하고 caveat에 적는다.
