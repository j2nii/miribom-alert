## 1. 과제 ① — 시계열 결과 시각화

### 1-1. 회의에서 나온 요청

회의록의 재은 항목을 그대로 옮기면 이렇습니다.

> - 그래프처럼 시각화가 잘 되어있어야 잘 보이지 않을까
>   - 바이럴 신호를 보여준다고 하는데 스파이크가 실제로 튀는걸 보여줘야하지 않을까
>   - 시계열 탐지 섹션에서 원래 그래프가 있음
>   - 이걸 조금 더 잘 보이는 위치에 두어야
>   - 시계열 에이전트의 결과를 조금 더 디자인적으로 괜찮은 그래프처럼 나오도록

### 1-2. 요청별로 어떻게 처리했나

| 요청 | 이전 상태 | 지금 |
| --- | --- | --- |
| **스파이크가 실제로 튀는 걸 보여주기** | 신호는 AREA 4 타임라인에 **글자 목록**으로만 있었습니다 | 검색 배율 곡선이 임계선(1.73배)을 뚫고 올라가는 모습을 그렸습니다. 임계를 7일 넘게 연속으로 넘은 구간은 붉은 띠, 확정일은 ◆로 표시합니다. 영월: **2/15 확정 → 3/7 최고 10.79배** |
| **원래 있던 그래프** | AREA 1의 예측 그래프. 축·눈금이 없는 선 하나였고, 제목은 "90일", 피크 목록에는 `예상 경보 undefined`가 떴습니다 | 새로 그렸습니다. 최근 6주 실측과 **같은 날을 7일 전에 예측한 값(백테스트)**을 겹치고, 그 뒤에 7일 예측과 80% 구간을 이어 붙였습니다 |
| **잘 보이는 위치** | AREA 1 = 반쪽 폭 스크롤 칸 안 | **AREA 0 바로 아래 전체 폭**. 상단 내비에 '↗ 추이·예측'이 있고, 사용법 투어에도 단계를 하나 추가했습니다 |
| **디자인적으로 괜찮은 그래프** | 라이브러리 없는 단순 SVG | 축·범례·호버 툴팁·'표로 보기'를 넣었습니다. 색은 dataviz 검증기에서 색각이상 구분 등 6개 항목을 모두 통과한 조합입니다. 좁은 화면에서도 넘치지 않습니다 |

### 1-3. 새 패널 구성

**요약 타일 3개** — 패널을 열자마자 결론이 보이게 했습니다(영월 기준).

| 검색 신호 확정 | 지점 최고 배율 · 3월 | 검색 신호 → 첫 행정 조치 |
| --- | --- | --- |
| **2/15** · 최고 10.79배(3/7) · 임계 1.73배 | **13.5배** · 단종장릉 · 같은 달 영월군 1.28배 | **19일 앞섬** · 사례 1건의 사후 확인 |

신호가 없는 지역은 타일에 "없음", 지점 자료가 없으면 "자료 없음"이 뜹니다. 조치 사건이 없는 지역은 세 번째 타일이 '7일 중 최대 예상'으로 바뀝니다.

**차트 ① 검색 관심과 외지인 방문 — 최근 1년**
- 위 칸은 검색지수의 전년 같은 요일 대비 배율(7일 중앙값)과 임계선입니다.
- 아래 칸은 외지인 방문자 7일 평균입니다. 전년 같은 요일을 회색으로 나란히 그립니다.
- 에이전트① 타임라인 사건(개봉 → 방문 급증 → 검색 신호 → 혼잡 → 조치)을 **번호 핀**으로 두 칸에 세로로 관통시켰습니다.
- 단위가 다른 두 지표는 한 축에 겹치지 않았습니다. 이중 축은 없는 상관을 만들어 보이게 하기 때문입니다.

**차트 ② 관광지점 vs 시군구 총량 — 전년 같은 달 대비**
- 지점과 총량을 **같은 잣대**로 한 그래프에 그렸습니다. 배율이라 로그축을 썼습니다.
- 영월: **단종장릉 13.5배 · 청령포 11.9배 vs 영월군 1.28배**. 총량이 움직인 폭은 지점 증가폭의 약 1/45입니다.
- 서식4 핵심 주장인 "총량은 지점 쏠림을 원리적으로 못 본다"를 그림 한 장으로 보여줍니다.

**차트 ③ 7일 방문객 예측**
- 이 지역의 백테스트 오차를 전국과 나란히 보여줍니다(영월 15.0%, 전국 8.98%).
- 피크일과 이유(예: 토요일 · 광복절 · 3일 연휴), 요일별 방문 비중을 함께 보여줍니다.

### 1-4. 숫자가 기존 문서와 어긋나지 않게 한 장치

차트는 **판정을 새로 만들지 않습니다.** 이미 쓰는 코드를 그대로 불러 화면용 파일로 옮겼습니다.

| 차트 요소 | 계산 코드 | 대조 결과 |
| --- | --- | --- |
| 검색·방문 배율, 임계, 신호 구간 | `agents/signals.py` (D-12) | 영월 2/15 확정·10.79배 — 에이전트① 타임라인과 같음 |
| 지점 vs 총량 배율 | `analysis/src/forecast/point_level.py` | 단종장릉 13.5배·청령포 11.9배·영월군 1.28배 — 사례 문서와 같음 |
| 백테스트·7일 예측 | `export_forecast.py` (h=7 검증 모델) | 테스트 sMAPE 8.98%를 재현한 뒤에만 내보냄 |

- **반올림**: 영월군 3월 원값은 1.275배입니다. 화면 기본 반올림은 부동소수점 오차로 이 값을 1.27로 내립니다. 그래서 사사오입 함수를 따로 써서 문서의 **1.28**과 똑같이 나오게 했습니다.
- **오해 방지**: 스파이크를 크게 보여줄수록 "검색으로 방문 급증을 예측한다"로 읽힐 위험이 있습니다. 그래서 차트 caveat에 이렇게 적었습니다.
  > "검색 신호는 급증을 미리 알려주지 않는다(조기경보 AUC 0.217, 지점 판별 AUC 0.482). 이 곡선은 사건을 사후에 확인하고 사례를 설명하는 용도다."

  확정수치 문서의 '쓰면 안 되는 문장'과 부딪히지 않게 하기 위해서입니다.

## 2. 과제 ② — 대상 지역 확장 ("타 지역 공무원도 쓸 수 있다")

### 2-1. 회의에서 나온 요청

> - 프론트에서 영월을 정했는데 영월을 대상으로 한다고 해야할까
>   - 영월, 거제는 예시로 - 나머지 지역들을 실시간 크롤링 가능하게 준비중이다 정도로
>   - 타 지역 공무원들도 사용 가능하다는 걸 어필 (지금은 데이터랩 데이터에 한해서만 사용 가능. 유튜브 등 기타 크롤링 자료는 사용 못함)

### 2-2. 진행 경과 — 두 단계로 했습니다

**1차(9/26 밤) — 데이터만 넓혔고, 화면은 부족했습니다**
- 7일 예측을 전국 226개 시군구 전부 만들었습니다.
- 지역 선택 목록을 3곳에서 7곳으로 늘렸습니다(여수·속초·인제·울릉 추가).
- **한계**: 선택 목록이 7개뿐이라 226곳 파일이 있어도 화면에서 고를 방법이 없었습니다. 추가한 4곳도 에이전트 산출물이 이미 있던 곳이라 "미리 골라 둔 사례 지역"이라는 인상이 그대로였습니다. 재은님도 확인 과정에서 "여전히 대상 지역이 한정적"이라고 지적했습니다.

**2차(9/27) — 지역 선택을 전국 검색으로 교체했습니다**
- 데이터랩 자료만으로 만들 수 있는 3종을 **전국 226곳 전부** 만들었습니다.
- `<select>` 목록을 **검색창**으로 바꿨습니다.
- 사례 지역과 나머지 지역을 화면에서 명확히 구분했습니다.

### 2-3. 어느 지역이든 나오는 것 / 사례 지역에만 있는 것

| 구분 | 항목 | 쓰는 자료 | 범위 |
| --- | --- | --- | --- |
| **데이터랩 기본 분석** | 경보 판정(3중 교차검증 신호등) | 데이터랩 월간 패널 + 이동통신 방문자 | **226곳** |
| | 신호 추이(검색·방문 배율) | 네이버 검색지수 + 이동통신 방문자 | **226곳** |
| | 7일 방문객 예측 | 이동통신 방문자 + 달력·축제 + 데이터랩 | **226곳** |

### 2-4. 검색 편의성 — 공무원이 실제로 치는 방식을 다 받습니다

| 이렇게 쳐도 | 찾아지는 것 |
| --- | --- |
| `강릉`, `강릉시` | 강릉시 (접미사 있어도 없어도) |
| `강원 고성` | 강원 고성군만 (경남 고성군과 구분) |
| `동구` | 동구 5곳이 시도와 함께 (광주·대구·대전·부산·울산) |
| `경북`, `전라북도`, `강원도` | 그 시도 전체 (약칭·옛 이름도 인식) |
| `ㄱㄹ`, `ㅇㅇ` | 초성 검색 (강릉·구례·계룡…) |
| `영 월` | 띄어쓰기가 틀려도 영월군 |
| `없는지역` | "맞는 시군구가 없습니다 — 시도 이름이나 초성으로도 찾을 수 있습니다" |

**그 밖의 편의 장치**
- **빈 칸을 누르면** 네 묶음이 뜹니다.
  - 전국 경보 분포 요약
  - 최근 본 지역
  - 심층 사례 지역(영월·거제 먼저)
  - 지금 경보가 높은 지역(포항·창원…)과 시도별 둘러보기(시도를 누르면 그 시도 전체가 나옴)
- **결과마다 배지**가 붙어 고르기 전에 상황을 봅니다. 경보 단계는 색과 글자를 함께 쓰고, '심층 사례'와 '검색 10.8배' 같은 신호도 표시합니다. 입력한 글자는 강조됩니다.
- **키보드**: 어디서든 `/`로 바로 검색, `↑↓`로 이동, `Enter`로 선택, `Esc`로 닫기. 스크린리더용 combobox 속성도 넣었습니다.
- **주소 공유**: 지역을 바꾸면 주소가 `?region=51820`처럼 따라 바뀌어 그대로 복사해 보낼 수 있습니다.
  - 사례 지역 코드(`?region=51750`)로 들어오면 영월 사례 화면으로 연결됩니다.
  - 사전에 없는 코드로 들어오면 영월로 돌아갑니다.
- **화면 구분 표시**
  - 전국 지역: "**데이터랩 기본 분석** — 공개 데이터(데이터랩·이동통신·검색지수)만으로 경보 판정·신호 추이·7일 예측 제공"
  - 사례 지역: "**심층 분석 사례 지역** — 유튜브·기사 등 수집 자료까지 연결"
  - 전국 지역에서 비어 있는 항목은 "이 항목은 영월·거제 등 심층 사례 지역에서 볼 수 있습니다"로 안내합니다. 빈 화면을 고장으로 읽지 않게 하기 위해서입니다.
- **챗봇**도 같은 규칙으로 전국 지역 자료를 읽습니다. 예를 들어 포항을 고르고 물어보면 포항 경보·예측으로 답합니다.

### 2-5. 원자료에서 바로잡은 것

- **광주광역시 5개 구(동구·서구·남구·북구·광산구)가 팀 DB에서 전라남도(시도 코드 12)에 섞여 있었습니다.**
  - 그대로 두면 "광주 동구"로 검색되지 않고, 동구가 '전남'으로 표시됩니다.
  - 검색 사전에서 광주광역시로 바로잡았습니다(`scripts/build_region_index.py`의 `GWANGJU`).
  - DB 자체는 수정하지 않았습니다. 필요하면 수영님께 DB 정정을 요청할 부분입니다.
- **인천 중구권·서구권**은 원자료가 여러 구를 합친 단위라 개별 조회가 불가능합니다. 목록에는 보이되 선택할 수 없고 이유를 표시합니다.

### 2-6. 회의 문구와 다르게 한 점

회의에서는 "나머지 지역은 **실시간 크롤링 가능하게 준비 중**"으로 말하자고 했습니다. 이 표현은 쓰지 않았습니다.
- **'실시간'은 사실이 아닙니다.** 방문자 자료는 4일 지연, 지점 자료는 월 단위입니다. 안내서 10장의 한계 표에서도 "월 단위 이상 감시"로 표현하기로 했습니다.
- **'준비 중'보다 '이미 된 것'이 강합니다.** 지금은 226곳이 실제로 동작합니다.

**서식4·발표용 제안 문구**
> "전국 226개 시군구는 공개 데이터(데이터랩·이동통신·검색지수)만으로 경보 판정·신호 추이·7일 방문객 예측을 즉시 제공한다. 영월·거제 등 6개 지역은 유튜브·기사 수집 자료까지 연결한 심층 분석 사례다."

### 3-2. 지은 휴먼인더루프 제안 검토

**지은 제안**: 체크리스트를 사용자가 UI에서 수정하고, 그 내용을 에이전트③이 다시 반영하게 하자.

**판단: 방향은 찬성. 다만 에이전트 재실행 대신, 같은 규칙을 브라우저에서 다시 적용하는 방식을 권했습니다.**

| 이유 | 설명 |
| --- | --- |
| 기술적으로 부담 | 에이전트③은 파이썬 + LLM 호출입니다. 사이트는 정적 JSON이고 Vercel에서는 Node 함수만 돕니다. 서버를 새로 만들고 배포·검증까지 캡처일(9/28) 전에 끝내기는 무리입니다 |
| 원문 수정 불가 | 조치 문장은 매뉴얼 원문 그대로여야 합니다(D-08, 공공누리 제4유형 변경금지). 사용자가 문장을 고치게 할 수는 없고, 메모는 따로 달아야 합니다 |
| 심사 방식 | 심사는 서식4 서면이고 웹은 캡처로만 들어갑니다. 하루 안에 되는 규모여야 합니다 |

**권고안 (우선순위순)**
1. **혼잡도 실측 입력 → '대기' 조치가 '발동'으로.** 에이전트③은 혼잡도가 미측정이라 현장 조치를 '대기'로 둡니다(D-07). 영월의 대기 3건은 조건이 모두 "혼잡도 3단계 이상 관측 시"라, 담당자가 단계만 입력하면 같은 규칙으로 바로 바뀝니다. LLM도 서버도 필요 없습니다. "도구가 모르는 유일한 값을 사람이 채운다"는 서식4에 쓰기 좋은 문장이기도 합니다.
2. **'완료' 옆에 '해당 없음 + 사유'와 현장 메모.** 원문은 그대로 두고 사람의 판단만 기록합니다.
3. **체크 상태를 챗봇에 전달.** "남은 조치 뭐야?"에 입력 상태를 보고 답하게 합니다.
4. 서버에서 에이전트③ 재실행은 서식4에 '확장 계획'으로 적습니다.

→ 지은이에게 보낼 답장 초안까지 만들어 두었습니다. **실제 구현은 아직 정하지 않았습니다**(6장 참고).

### 3-3. Vercel 배포 문제 진단

- **현상**: 재은이 UI/UX에 푸시(9/27 15시)한 뒤에도 지은이 공유한 주소는 옛 버전 그대로였습니다. 새 파일은 404가 났습니다.
- **진단**: 배포된 화면 코드에 '추이·예측'이 없고, 캐시 나이가 푸시 이전이었습니다. 즉 **Vercel이 재은 커밋을 배포하지 않은 것**입니다. 가장 유력한 원인은 Vercel 무료(Hobby) 요금제의 제한입니다. 프로젝트 주인(j2nii)이 아닌 사람이 작성한 커밋은 배포하지 않습니다.
- **결과**: 지은이 9/27 21:43에 PR #11을 develop에 병합했습니다. 병합 커밋 작성자가 지은이라 **develop 배포 주소에는 전부 반영됐습니다.** 9/28에 그 주소에서 새 파일 200 응답, 영월 요약 타일, '강원 고성' 검색, 기본 분석 표시를 직접 확인했고 오류는 없었습니다.
- **남은 것**: UI/UX 미리보기 주소(`…-git-ui-ux-…`)는 여전히 옛 버전입니다. **캡처는 develop 주소로 해야 합니다.**

### 3-4. 그 밖에

- **좁은 화면 레이아웃**: 태블릿·휴대폰 폭에서 그리드 열이 가장 넓은 내용(차트·채팅창)만큼 늘어나 화면 밖으로 밀리던 기존 문제를 `index.css` 한 줄로 고쳤습니다.
- **로컬 실행 환경**: `web/.env`가 없어서 로컬에서 챗봇이 안 되고, 거제 콘텐츠 분류가 목업으로 뜨고 있었습니다(`VITE_USE_PROD` 꺼짐). 최상위 `.env`의 키로 `web/.env`를 만들었습니다(git에는 안 올라감).
