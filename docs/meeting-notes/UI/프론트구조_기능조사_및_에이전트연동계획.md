# 프론트 구조 기능 조사 및 5개 에이전트 연동 계획

> `회의준비_진행상황정리_v3.md` 기준 · 작성 2026-09-16 · 대상 브랜치: `UI/UX`

`회의준비_진행상황정리_v3.md`가 정의한 기능·에이전트 목록을 현재 `UI/UX` 브랜치의 실제 프론트 구현(React+Vite, `web/`)과 대조해 "문서에는 있지만 지금 프론트 구조로는 쓸 수 없는 기능"을 찾고, 5개 에이전트가 프론트와 어떻게 이어지는지(현재 상태 + 이어야 할 방식)를 정리한다.

조사 방법: `web/` 전체(페이지·컴포넌트·데이터 로딩·API), `data/` 목업/스키마, `agents/`·`collection/`·`scripts/`, `docs/설계결정.md`, `docs/meeting-notes/역할34_재분배_및_주간체크리스트.md`를 직접 읽어 확인.

---

## 1. 조사 결론 요약

- 프론트는 AREA 0~4 다섯 화면이 전부 실제로 동작한다 (React 컴포넌트, 로딩/에러 상태, region 전환 포함). 단, **모든 화면이 사전 생성된 JSON을 그대로 렌더링**할 뿐 — 판정·예측·매칭·분류 로직은 어디에도 client/server 계산으로 존재하지 않는다.
- **완전히 빠진 기능**: 자연어 질의 인터페이스 (채팅 UI, 도구 호출 코드 전무).
- **프론트 슬롯은 있으나 실제 연결이 안 된 기능**: 에이전트①(타임라인 추출), ③(매뉴얼 매칭), ④(선례 조사) — 렌더 컴포넌트는 존재하지만 그 데이터를 만드는 스크립트/프롬프트가 없거나("작성 예정") mock만 소비.
- **부분적으로만 실제**: 에이전트②(콘텐츠 유형 분류) — 실제 YouTube 데이터 + 수작업으로 실행한 LLM 결과가 있지만 `VITE_USE_PROD` 플래그가 기본 꺼져 있어 프론트는 기본적으로 mock을 보여줌.
- **유일하게 실시간으로 붙어 있는 에이전트**: ⑤(브리핑 생성) — `BriefingGenerator.jsx → web/api/briefing.js → Upstage Solar` 실호출. 단 `vercel dev`/배포 환경에서만 동작, 순수 `vite dev`에서는 자동으로 로컬 규칙 기반 템플릿(`lib/briefingTemplate.js`)으로 폴백된다.
- **지역 불일치**: `manifest.js`가 아는 지역은 `geoje`, `chungju` 뿐. 문서가 논의 중인 MVP 후보 "거제+경주"의 **경주(Gyeongju)는 프론트에 아예 등록되어 있지 않다.**
- **데이터 소스 불일치**: 관광 데이터랩(한국관광 데이터랩) API에 대한 실제 호출 코드가 프로젝트 어디에도 없다 — `scripts/gen_mock.py`가 소스 라벨 문자열로만 언급. B(90일 예측)·C(요일별 집중률)·D(방문객 프로파일)·F(유사지역 선례) 데이터는 전부 데이터랩 제공을 전제하지만 수집 파이프라인이 없다 (`collection/datalab_export/`는 `.gitkeep`만 있는 빈 폴더).
- **H(유입·유출 파급 예측)**: 9종 JSON 스키마 목록에 아예 없음 — schema·frontend 슬롯 자체가 없다.

## 4. 연결 계획 (제안)

기존 패턴("오프라인 배치 스크립트 → 스키마 준수 JSON → `data/mock`or`data/prod`에 드롭 → 프론트는 무변경으로 자동 소비")을 그대로 따르는 것이 최소 변경으로 가장 빠르다. 프론트 쪽 렌더 컴포넌트(①③④ 전부)는 이미 존재하므로 **프론트 코드 수정 없이 에이전트 스크립트만 추가하면 연결된다.**

1. **에이전트③ (매뉴얼 매칭) — 우선순위 최상** (`checklist.json`이 AREA3의 핵심)
   - `agents/prompts/agent3_manual_match.md` 작성 (설계결정 D-03의 3단계 필터 + `content_type` 가중치 정렬 규칙을 프롬프트/로직으로 구현)
   - `agents/agent3_apply.py`: 역할4가 구조화한 매뉴얼 태그(단계/유형/프로파일 축) + 현재 `alert_level`/`content_type`/`profile_tags`를 입력받아 규칙 기반 필터링은 코드로, 의미적 매칭이 필요한 부분만 LLM 사용 → `checklist.schema.json`의 `items[].rank` 포함해 출력
   - 결과를 `data/mock/checklist.json`(또는 `data/prod/`)에 드롭 — `ChecklistPanel.jsx`는 무변경으로 즉시 반영

2. **에이전트④ (선례 조사)**
   - `agents/agent4_apply.py`: 데이터랩 유사지역 목록(수집 파이프라인 필요 — §5 참고) + 뉴스/보도자료 검색·요약(LLM) → `precedent.schema.json` 준수 출력
   - `PrecedentCards.jsx` 무변경으로 소비

3. **에이전트① (타임라인 추출)**
   - `agents/agent1_apply.py`: 뉴스·공고 검색 → 바이럴 기점/방문 급증/행정 대응 시점 구조화 추출(LLM) → `timeline.schema.json` 출력
   - `LeadTimeTimeline.jsx` 무변경으로 소비

4. **에이전트② (콘텐츠 유형 분류) — 이미 반쯤 연결됨, 마감 작업**
   - `agent2_apply.py`의 하드코딩 `RESULTS` dict를 실제 LLM API 호출로 교체(현재 최대 기술부채)
   - `VITE_USE_PROD=true` 전환 또는 `manifest.js`에서 `content_type`을 지역별로 `kind: "real"`로 승격해 기본 노출

5. **에이전트⑤ (브리핑 생성) — 보완**
   - 인라인 `SYSTEM_PROMPT`를 `agents/prompts/agent5_briefing.md`로 추출(문서·설계결정 D-04와 정합성, 심사 자료로도 재사용 가능)
   - 로컬 개발 시 `vercel dev`로 구동하도록 팀 README/스크립트에 명시하거나, 최소한 이 제약을 역할3·4가 인지하도록 문서화
   - 데모 안정성을 위해 사전 생성된 브리핑 스냅샷(JSON) + "재생성" 버튼으로 실시간 호출을 보조 기능화하는 방향 권장(이미 존재하는 폴백 템플릿이 안전망 역할)

6. **자연어 질의 인터페이스 — 신규 구축 필요 (스트레치 골)**
   - 신규 Vercel 함수 `web/api/query.js`: 자연어 질문 + region을 받아 함수 호출(tool-calling)로 §4의 8개 `get_*`/`compare_*` 도구를 실행. 각 도구는 서버 사이드에서 기존 `data/mock|prod/*.json`을 읽는 얇은 래퍼 — 이미 있는 9종 JSON 계약을 그대로 도구로 노출하는 것뿐이라 신규 데이터 작업은 불필요
   - 프론트: 새 채팅 위젯(예: AREA0 헤더 또는 별도 모달) → `fetch('/api/query')`, 응답은 기존 `SourceBadge`/`CaveatNote` 컴포넌트로 출처·caveat 표시(일관성 유지)
   - 의존관계상 ②③④가 실데이터로 채워진 뒤에 의미가 커지므로 W3~W4 단계로 순서 배치 권장

7. **경주(Gyeongju) 지역 지원**
   - MVP 지역이 "거제+경주"로 확정되면 `manifest.js`에 `gyeongju` 엔트리 추가 + 해당 9종 mock/prod JSON 생성(`scripts/gen_mock.py` 확장) 필요 — 현재는 프론트 선택지에 전혀 없음

8. **관광 데이터랩 API 연동 (B·C·D·F의 실데이터 전제)**
   - `collection/datalab_export/`가 빈 폴더로 예약되어 있음 — 데이터랩 다운로드/파싱 스크립트 추가가 선행되어야 B(90일 예측)·C(집중률)·D(프로파일)·F(유사지역)가 mock을 벗어날 수 있음. 이는 "역할1(데이터 수집)" 영역이라 에이전트 연결과는 별개 트랙.

## 5. 우선순위 근거

`docs/meeting-notes/역할34_재분배_및_주간체크리스트.md`가 이미 "에이전트①④ 구현은 다음 주, 사전 생성 JSON으로 충분", "실시간 LLM 호출 배포 판단은 다음 주"라고 명시했다 — 즉 이번 조사가 찾아낸 미연결 상태 대부분은 **팀이 의도적으로 순서를 미룬 것**이지 누락이 아니다. 다만 다음 두 가지는 문서화되지 않은 실제 차이이므로 회의에서 짚을 가치가 있다:
- 경주 지역이 프론트에 전혀 없다는 점 (MVP 지역 결정 시 즉시 필요)
- 에이전트⑤가 로컬 `vite dev`에서 항상 폴백된다는 점 (팀원들이 "AI 호출이 안 된다"고 오인할 수 있음)
