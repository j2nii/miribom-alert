# 에이전트 현황 및 프론트 매핑 문서 작성 계획

## Context

9개 데이터 계약(+briefing)별로 "LLM을 쓰는지, 하드코딩인지, 하드코딩이면 왜 유지해야 하는지"를 하나씩 확인했다(에이전트②는 LLM으로 교체해야 할 확정 기술부채, 에이전트③⑤는 이미 LLM 연동됨, hotspots의 spatial_type은 설계 문서상 원래 규칙/하드코딩이 맞음, 에이전트④는 아직 미구현이지만 원래 LLM 기반으로 계획됨). 이 내용을 팀이 참고할 수 있는 문서 한 곳에 정리하고, 각 항목이 프론트 어디에 어떻게 나타나는지 실제 화면 캡처와 함께 남긴다.

**문서 구성 방침**:
- LLM 호출 부분: 프롬프트 파일 위치, 모델/프로바이더, 무엇을 판정하는지 정리
- LLM으로 교체 예정인 하드코딩(에이전트②): 개요만 정리(상세 판정 결과는 교체 후 채울 것이므로 비워둠)
- 계속 하드코딩으로 남아야 하는 부분(hotspots의 spatial_type 룩업): 이유 + 실제 하드코딩된 내용 자체를 문서에 옮겨 적음
- 각 항목마다 "프론트 어디에 나타나는가"를 실제 화면 캡처로 보여줌

## 실행 시점

지금은 이 계획 문서만 저장해둔다. 실제 캡처·문서 작성은 아래 두 가지가 끝난 뒤 진행한다:
1. 에이전트②(content_type) LLM 연동 교체 완료
2. hotspots/visitor_profile 등 프론트(`manifest.js`/`dataManifest.js`) 반영 완료

그래야 캡처가 최종 상태를 담고, 다시 찍을 필요가 없다.

## 캡처 방법 (실행 시)

현재 환경에 브라우저 자동화 도구가 없어(playwright/puppeteer 미설치), `web/`에 playwright를 devDependency로 임시 설치해 로컬에서 직접 캡처하고 작업 후 제거한다(`npm install --no-save`로 package.json에 흔적 안 남김 — 이번 세션 mysql2 임시 설치 때와 동일 방식).

1. `npm install --no-save -D playwright` (+ `npx playwright install chromium` 필요할 수 있음)
2. `npm run dev:api` (백그라운드) + `npm run dev` (백그라운드)로 로컬 서버 기동
3. playwright 스크립트로 `http://localhost:5173` 접속 → region select를 `geoje`로 변경(9종 계약이 다 채워진 지역) → 각 AREA 패널 캡처
4. 필요하면 `yeongwol`로도 한 번 더(실측화한 signal_status/timeline 확인용)
5. 캡처 파일은 `docs/meeting-notes/UI/screenshots/`에 저장 (레포 관례상 `docs/submission/figures/`처럼 문서 옆에 이미지 두는 패턴을 따름)
6. 문서 작성 후 playwright 제거, `git status`로 node_modules 변경이 커밋 후보에 안 걸리는지 확인

## 작업 순서 (실행 시)

1. playwright 임시 설치, dev 서버 2개 기동
2. 거제(및 필요시 영월) 화면에서 AREA0~4 캡처, `docs/meeting-notes/UI/screenshots/`에 저장
3. 위 매핑 표를 뼈대로 각 항목별 절 작성 — LLM/하드코딩-교체예정/하드코딩-유지 세 갈래로 서식 구분
4. hotspots spatial_type 절에는 `agents/agent_hotspots.py`의 `POI_SPATIAL_TYPE` 테이블 전체를 문서에 옮겨 적고, 상단에 "왜 유지하는가"(D-04 표 인용) 명시
5. content_type 절은 개요만: 무엇을 분류하는지, 지금 상태(하드코딩), 교체 계획(agent2_content_type.md 프롬프트 + llm_client.complete_json 연결)만 적고 판정 결과 상세는 비워둠
6. checklist/briefing 절은 프롬프트 파일 경로, 모델(solar-pro3), D-08/D-11 요약, 실제 실행 로그(`agents/runs/*.json`) 경로 언급
7. 캡처·문서 다 만든 뒤 dev 서버 종료, playwright 제거, `git status`로 정리 상태 확인
