# 누출 점검표 — 예측 시점에 알 수 있는 변수만 쓴다

> 작성 2026-09-22 · 시계열 담당(재은) · 대상: `data/interim/panel_daily.csv`
> 판단 기준: **예측하려는 날(t)보다 앞서 실제로 손에 들어오는 값인가.** 아니면 쓰지 않는다.

---

## 왜 이 표가 필요한가

백테스트에서 오차가 작게 나오는 가장 흔한 이유는 모델이 좋아서가 아니라 **미래 정보를 몰래 쓴 것**이다. 예를 들어 "그날 비가 왔는가"를 넣으면 예측이 좋아지지만, 실제 운영에서 일주일 뒤 강수량은 알 수 없다. 심사에서 이 질문이 나오면 답할 수 있어야 하므로, 변수마다 판단을 미리 적어 둔다.

데이터랩 공개 주기는 한국관광 데이터랩 공지 기준이다. 이동통신 일별은 4일 전, 내비게이션 6일 전, 신용카드 11일 전 자료가 올라오고, 지역별 월간 분석은 매월 17일에 전월분이 공개된다.

## 날씨 처리 — 모델을 둘로 나눈다

날씨는 "과거 관측"이고 예보가 아니다. 예측 시점에 일주일 뒤 강수량을 알 수 없으므로, 날씨를 넣은 모델은 **실제보다 좋게 나온다.** 그래서 두 가지를 따로 만들고 둘 다 보고한다.

| 모델 | 날씨 변수 | 의미 |
| --- | --- | --- |
| 운영 모델 | 날씨 없음 (또는 t-1까지의 과거 날씨만) | 실제로 돌릴 수 있는 성능 |
| 상한 모델 | 그날 실측 날씨 포함 | 날씨를 완벽히 예보한다면 얻는 최대 성능 |

서식4에는 **운영 모델 수치를 주로 쓰고**, 상한 모델은 "날씨 정보를 붙이면 여기까지 올라간다"는 보조 설명으로만 쓴다.

---

## 데이터 처리 규칙

1. **강수량 NULL은 0이다.** ASOS는 비가 오지 않은 날을 빈칸으로 둔다. 패널에서 0으로 채우고 `precip_was_null`로 표시했다 (전체 행의 40.0%)
2. **날씨 미매핑 79개 지역은 버리지 않는다.** `weather_available=0`으로 두고 집계를 따로 낸다. 사례 지역 중 **울릉군에는 ASOS 매핑이 없다**
3. **랜덤 분할 금지.** Train 2023-01~2024-12 / Valid 2025 / Test 2026-01~2026-08-14
4. **표준화·임계값은 학습 구간에서만** 계산한다
5. **기준일**: 관측 마지막 날 2026-08-14. 문서에는 "데이터 기준일"과 "가상 기준시점"을 함께 적는다
