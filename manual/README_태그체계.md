# 매뉴얼 체크리스트 구조화 작업 안내

작업 대상: `지속가능한 관광지 혼잡도 운영 관리 매뉴얼` (한국관광공사, 2026.03, 57쪽)
결과물: `manual/checklist_items.json` — 샘플은 `manual/checklist_items.sample.json`

---

## 무엇을 만드는 작업인가

매뉴얼에 흩어져 있는 **조치 항목**을 한 건씩 JSON 레코드로 옮긴다.
이 파일은 시스템이 "지금 상황(경보 단계 + 공간 유형 + 방문객 특성)에 해당하는 조치"만 골라 화면에 띄우는 **검색 인덱스**가 된다.

핵심 원칙 하나: **조치 문장을 새로 쓰지 않는다.** 매뉴얼에 있는 표현을 그대로 옮기고, 어느 쪽 어느 절에서 왔는지 `근거`에 적는다. 이 근거 표시가 "AI가 정책을 창작하지 않는다"를 화면에서 증명하는 장치다.

## 필드 설명

| 필드 | 필수 | 값 | 설명 |
| --- | --- | --- | --- |
| `id` | O | `CL-001` 형식 | 001부터 순번. 중간에 비는 번호가 있어도 무방 |
| `시점` | O | 아래 4개 중 하나 | 하루 중 언제 하는 조치인가 |
| `단계` | O | 배열 | 이 조치가 발동하는 경보 단계 |
| `혼잡도단계` | O | 배열 (1~5) | 밀도 기준 단계. 매뉴얼 p.53 |
| `공간유형` | O | 배열 | **비어 있으면 전 유형 공통**이라는 뜻 |
| `프로파일` | O | 배열 | 방문객 특성 조건. 대부분 비어 있음 |
| `상황유형` | - | 배열 | 매뉴얼 p.39처럼 **혼잡 상황 유형별로 묶인 조치**에만 붙인다. 없으면 필드 생략 |
| `조치` | O | 문자열 | 매뉴얼 표현 그대로 |
| `담당` | O | 문자열 | 매뉴얼 p.7~8의 주체 명칭 사용 |
| `우선순위` | O | `최우선`/`높음`/`보통` | 매뉴얼에 "최우선" 표기가 있으면 그대로 |
| `근거` | O | 객체 | 문서·쪽·절·원문 4개 필드 전부 채움 |

### 값 목록 (이 목록 밖의 값을 쓰지 않는다)

**시점**
```
사전(예보 대응) / 오전(준비) / 운영 중(모니터링) / 비상 대응 / 마감(평가)
```
`사전(예보 대응)`은 **며칠 앞서** 준비하는 조치다 (p.20 시나리오 ①②, p.13 유형별 관리, p.18~19 계획 수립). 나머지 4개는 p.50의 하루 일과 구분이다. 설계결정 D-07 참조.

**상황유형** — 매뉴얼 p.39 (선택 필드)
```
유입 급증형 / 병목 정체형 / 안전 위험형 / 민원 급증형
```

**단계** — 경보 단계 (매뉴얼 p.10)
```
관심 / 주의 / 경계 / 심각
```

**혼잡도단계** — 밀도 기준 1~5 (매뉴얼 p.53)
```
1: 0.2명/㎡ 이하 (매우 낮음)
2: 0.2~0.4명/㎡ (낮음)
3: 0.4~0.6명/㎡ (보통)
4: 0.6~0.8명/㎡ (높음)
5: 0.8명/㎡ 초과 (매우 높음)
```

**공간유형** — 매뉴얼 p.13 공식 4분류
```
네트워크 보행 흐름형
지형·경사 이동·저항 흐름형
실내 공간 가치 체류 중심형
실외 공간 가치 체류 중심형
```

**프로파일** — 필요한 경우에만. 예시:
```
20대비중높음 / 당일치기우세 / 외지인우세 / 단체방문우세
```

## 어디서 항목을 뽑는가 — 진행 현황

결과물은 `manual/checklist_items.json` 하나다. **역할4가 에이전트③ 테스트에 필요한 35건을 먼저 채웠다.** 이어서 아래 '남음' 범위를 같은 파일에 추가하면 된다.

| 매뉴얼 위치 | 내용 | 상태 | id 대역 |
| --- | --- | --- | --- |
| p.50 부록 일일 운영 실무 가이드 | 오전·운영중·비상·마감 17건 | **완료** | CL-001~018 (010 결번) |
| p.13 관광지 유형 분류 | 유형별 `관리:` 4건 | **완료** | CL-023~026 |
| p.39 상황별 즉각 대응 | 상황 유형별 대응 패키지 4건 | **완료** | CL-030~033 |
| p.20 운영관리 시나리오 ①② | 상시 운영체계, 사전 예보 프리셋 8건 | **완료** | CL-040~047 |
| p.37 경고 알림 시스템 | 단계별 자동 대응 2건 | **완료** | CL-050~051 |
| p.20 운영관리 시나리오 ③~⑦ | 각 단계 4개 항목 | 남음 (20건) | CL-060~ |
| p.18~19 운영관리 계획 수립 | 운영관리 체계·인력·교통대책·상황별 대처 계획 | 남음 | CL-080~ |
| p.35, p.38 교육·훈련, 관광객 안전 관리 | 대응 매뉴얼 숙지, 대피·응급·물리적 안전 | 남음 | CL-100~ |
| p.40 관광지 유형별 대응 | 유형 1~4 대응 방안 예시 | 남음 (8건 내외) | CL-120~ |

**묶을지 쪼갤지**: 매뉴얼이 **패키지로 제시한 조치는 1건으로 둔다.** p.39는 "상황 유형을 우선 판별 후 대응 패키지 적용 / 단일 조치보다 복합 조치 병행 원칙"을 명시하고, p.13 `관리:`도 유형별 한 묶음이다. 반대로 p.20·p.50처럼 불릿으로 나열된 조치는 불릿 하나가 1건이다.

**원문 판독**: PDF에 텍스트 레이어가 없다. 작은 글씨는 확대해서 확인할 것 — p.20 ②의 "강화(우천·야간·대형행사)"는 원본 크기로는 "주전"처럼 보인다.

## 자주 나오는 실수

1. **조치를 요약하거나 다듬는 것** — 매뉴얼은 공공누리 4유형(변경금지)이다. 원문 표현을 유지한다.
2. **`근거.원문`을 비우는 것** — 이 필드가 비면 화면에 항목이 뜨지 않도록 설계되어 있다.
3. **공간유형에 전부 4개를 넣는 것** — 전 유형 공통이면 빈 배열 `[]`로 둔다. 4개를 다 넣는 것과 결과는 같지만, "이 조치는 유형 무관"이라는 정보가 사라진다.
4. **단계를 하나만 넣는 것** — "주의 이상에서 계속 유효한 조치"라면 `["주의","경계","심각"]`처럼 해당 단계를 모두 넣는다.
5. **현장 조치의 혼잡도단계를 전부 넣는 것** — "4단계(높음) 감지 시" 같은 조건이 있는 조치는 `[4, 5]`처럼 조건 단계만 넣는다. 이 값이 있어야 선행 신호만으로 현장 통제 조치가 나가는 사고를 막는다(D-07). 사전 준비 조치는 `[1,2,3,4,5]`.
